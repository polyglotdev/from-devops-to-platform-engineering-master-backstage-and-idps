What "Listening on a Port" Means

A container has many ports (like doors on a building), but only the ports where your application is actively listening will respond to requests. Port 8000 is glowing green because FastAPI/Uvicorn is listening there.

uvicorn.run(app, host="0.0.0.0", port=8000)

The app binds to 0.0.0.0:8000 - listening on all interfaces, accepting external traffic

Services: Stable Endpoints with Load Balancing

Pods are ephemeral - they come and go with new IP addresses. A Service provides a stable IP and DNS name that never changes, and load balances traffic across all healthy pods.

Why Services Matter:

  • Pod IPs change when pods restart - Service IP stays the same
  • Other apps use the DNS name, never hardcode pod IPs
  • Traffic is distributed across healthy pods automatically

Ingress Controller vs Ingress Resource

Two different things, both called "Ingress". Understanding the difference is key to setting up external access correctly.

Ingress Controller

The actual running NGINX pods that receive traffic

  • Installed once per cluster
  • Lives in ingress-nginx namespace
  • The "receptionist" at the door
  • Reads all Ingress Resources
kubectl get pods -n ingress-nginx

Ingress Resource

A YAML config defining routing rules

  • One per app/service you expose
  • Lives in your app's namespace
  • The "directory" listing
  • Maps hostname to service
kubectl get ingress -n platform-demo

Ingress Controller = Receptionist at building entrance
Ingress Resource = Directory that says "FastAPI App is in Room 80"
